Ranking Content Opportunities Using Search-Performance Signals

A machine-learning study for prioritizing content pages for human review.

🌲 Random Forest 🔬 Client-grouped validation 📊 Precision@20 🛡️ Decision support

Abstract

This project investigates whether search-performance and content signals can be used to rank pages that show signs associated with decline. I trained a Random Forest classifier using 29 search, engagement, content-age, and performance features and evaluated it using a client-grouped train/test split. On the held-out test set, the Random Forest measured a Precision@20 of 1.00 compared with 0.45 for the Week-4 heuristic baseline. The resulting ranking is intended as directional decision support for prioritizing pages for human review, not as proof of causation or a guarantee of future performance.

1. Introduction / Problem Statement

Content teams may have many pages that require attention, making it difficult to decide which pages should be reviewed first. This project explores whether available search-performance and content signals can help prioritize those pages.

Research Question

Can search-performance and content signals be used to rank content pages that show signs associated with decline, so that a content team can prioritize pages for human review?

The model supports prioritization. It does not automatically decide whether a page should be refreshed, deleted, redirected, or otherwise changed.

2. Data

The project uses the anonymized search dataset provided for the FlyRank ML Internship. The dataset contains 30,000 records and 44 original columns.

Target Definition

A binary target called is_declining_label was created from the trend direction. Pages whose trend direction was down were assigned a value of 1. Other pages were assigned 0.

Excluded Signals

trend_direction and trend_pct were excluded from the model features because they are directly related to the target. Including them could expose information about the outcome being predicted.

Random Forest

I used a Random Forest classifier with 200 decision trees, a fixed random seed, balanced class weights, and parallel processing. Missing numerical values were handled using median imputation.

Validation

Instead of randomly splitting individual pages, I used a client-grouped 80/20 train/test split. Pages belonging to the same client were kept together.

5. Limitations & Honest Framing

This analysis was evaluated on one dataset using one client-grouped test split. Performance may differ on future data, other clients, or other datasets.

Precision@20 measures the quality of the highest-ranked pages in this test set. It does not prove that the model will always rank useful pages first.

Feature importance indicates which signals the model relied on. It does not establish that those signals caused a page to decline.

The model identifies pages associated with the declining label. It does not establish why a page declined and does not guarantee that refreshing a page will improve its performance.

Decision-support boundary

The output should be treated as decision support for human review, rather than as an automatic content-management system.

6. Ranked Recommendations

The model produces a ranked queue based on its estimated probability of the declining class. Reason codes provide supporting signals that help reviewers understand why a page may have been prioritized.

RECENT_IMPRESSION_DECLINE Recent impressions are below the previous period.
LOWER_CTR CTR is below the dataset median.
OLDER_CONTENT Content age is above the dataset median.
STALENESS Days since the last update are above the dataset median.
WEAKER_POSITION Average position is weaker than the dataset median.

These reason codes are supporting signals rather than causal explanations. A human reviewer should evaluate the actual page and context before deciding what action, if any, is appropriate.

7. Reproducibility

The analysis is implemented in the project's Jupyter/Colab notebooks. The capstone notebook contains dataset loading, feature preparation, client-grouped validation, model training, baseline comparison, leakage checking, recommendation ranking, and artifact generation.

The final artifacts include a model comparison table, ranked action queue, and feature-importance output.

The project is maintained in the FlyRank ML Internship GitHub repository.

8. Decision-Support Summary

The final system turns a machine-learning prediction into a ranked content-review queue. The purpose is to help humans focus attention on pages that show signals associated with decline.

The measured test result supports using the ranking as a directional prioritization tool within the evaluated setting. It should not be interpreted as evidence about Google's ranking algorithm or as proof that a particular content intervention will cause better performance.
